# Remaining Divergence Tasks

- [x] Reconcile mount API with the rebased design docs. Current code still exposes `EndoMountEntry.exists/stat` and `openFile/openDirectory/createFile/createDirectory`, while the target design says entries are value-only and uses `has/stat/lookup(entry)` plus `makeFile/makeDirectory`. See `packages/daemon/src/mount.js:515` and `designs/daemon-mount-capabilities.md:207`.
  - [x] Strip `exists()` and `stat()` from `makeMountEntryExo` (`packages/daemon/src/mount.js:515-534`) and from `MountEntryInterface`; `EndoMountEntry` then holds only `segments()`, `displayPath()`, `child()` (and `help`). Drop the `resolveEntry`/`assertConfined` plumbing those two methods rely on so the entry never reaches the backing filesystem.
  - [x] Add `has(entry)`, `stat(entry)`, and `lookup(entry)` overloads on `EndoMount` (the path-form variants currently at `packages/daemon/src/mount.js:304`, `:333`, and `:415`) so the mount stays the single authority for observation and handle-minting. Extend `MountInterface` accordingly; verify entry provenance against `mountEntryRecords` and the mount's `rootId` before honoring the entry.
  - [x] Remove `openDirectory`/`openFile`/`createDirectory`/`createFile` (`packages/daemon/src/mount.js:344-413`). `lookup(path|entry)` already covers both kinds for opening; for the constructive case add `makeFile(path, content?)` as the sibling of the existing `makeDirectory`, accepting `string | Uint8Array` content and writing through `filePowers`.
  - [x] Update `EndoMount` / `EndoMountEntry` declarations in `packages/daemon/src/types.d.ts` and migrate in-tree callers (the Fae git adapter and mount tests under `packages/daemon/test/`) from the removed methods to `lookup` / `makeFile`. Track Phase 2 / Phase 3 checkbox completion in `designs/daemon-mount-capabilities.md` § Implementation Plan once the migration lands.

- [x] Align `provideGit` with the design: the code still supports pet-name lookup and rejects read-only mounts; the design says cap-passing is normative and `provideGit(readOnlyMount)` should return read-only Git. See `packages/daemon/src/host.js:336`.
  - [x] Delete the pet-name branch in `provideGit` (`packages/daemon/src/host.js:336-349`): drop the `NameOrPath` arm of `mountRef`, the `assertNamePath(mountNamePath)` call, and the `E(directory).lookup(mountNamePath)` resolution. Callers that need name → cap go through `E(host).lookup(name)` first, matching `designs/daemon-git-capability.md` § Capability Construction.
  - [x] Replace the read-only rejection (`packages/daemon/src/host.js:355-364`) with read-only **propagation**: when the resolved mount formula has `readOnly: true` (or the cap was obtained via `mount.readOnly()`), still allow construction but pass a `readOnly: true` flag into `formulateGit` so the resulting `Git` is born read-only — per `designs/daemon-git-capability.md` § Read-only construction paths and Design Decision 8.
  - [x] Thread that flag through the `git` formula type (`packages/daemon/src/types.d.ts` git-formula entry) and through `makeGitExo` / the git capability factory so `add`/`commit`/`switch`/etc. throw on a read-only `Git`, while still allowing `tree(ref)`, `status`, `diff`, `log`, `show`, `revParse`, `branches`, `currentBranch`, `worktree().snapshot()`, and `readOnly()` (idempotent).
  - [x] Add restart/persistence and same-authority-shape tests confirming `provideGit(readOnlyMount)` and `await E(writableGit).readOnly()` return caps with identical `__getMethodNames__` and identical throw-on-mutation behavior (the Capability Tests listed in `designs/daemon-git-capability.md` § Testing Plan).

- [ ] Replace credential helper/state-file injection with the planned anonymous-pipe/fd askpass path. Current code persists credential secret state and passes `secretPath` to a helper command. See `packages/daemon/src/daemon.js:719` and `packages/daemon/src/daemon-node-powers.js:629`.
  - Delete the on-disk credential store (`writeGitCredentialState` / `readGitCredentialState` / `gitCredentialStatePath` at `packages/daemon/src/daemon.js:707-736` and `rotateGitCredential`'s persistence at `:788`+). Replace it with an in-process sealed slot keyed by formula number that survives only the daemon's lifetime; on restart, the credential cap is `revoked: true` until the operator re-supplies the secret via `EndoGitCredentialController.rotate()`. This is what `designs/daemon-git-remotes.md` § Transport and Backend Boundary calls "no secret in argv / env / persisted state".
  - Rewrite `runGitCredentialed` (`packages/daemon/src/daemon-node-powers.js:621-648`). Drop the `credential.helper=!node helper ${secretPath}` argv flag and the helper-script + `secretPath` plumbing (`ensureCredentialHelper`, the `GIT_CREDENTIAL_HELPER_SOURCE` write at `:610`). Replace with: ship a tiny daemon-bundled `git-askpass` helper binary, spawn it via `GIT_ASKPASS=<helperPath>` with `GIT_TERMINAL_PROMPT=0`, and pass the secret over an `O_CLOEXEC` anonymous pipe whose read-end fd the helper inherits (macOS: `pipe()` + `fcntl(FD_CLOEXEC)`). Also pass `-c credential.helper=` to empty the ambient helper list, and keep `cancelled` plumbing so the pipe is closed on revocation.
  - Update `GitCredentialUse` in `packages/daemon/src/types.d.ts:1075` to drop `secretPath: string` and instead carry an opaque sealed-secret handle that the daemon resolves at spawn time. `inspect()` already omits the secret; double-check that no diagnostics path logs it.
  - Treat bearer-token support as **gated by the credential-injection spike** named in `designs/daemon-git-remotes.md` § Spike: confirm credential-injection portability — basic credentials ride the askpass path first; bearer ships only once the spike confirms `/proc/<pid>/environ`, `/proc/<pid>/cmdline`, the helper temp dir, and `GIT_CONFIG_*` files are clean per credential type.
